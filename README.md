# TestBuddy demo

[![Java 21+](https://img.shields.io/badge/Java-21%2B-blue)](https://openjdk.org/)

A small two-module Maven project that shows TestBuddy's output with and without a validation provider. Use it to see the difference, and to check your IDE setup.

## Requirements

- Java 21 or later
- Maven 3.9 or later
- IntelliJ IDEA 2025.3 or later with the TestBuddy plugin, to generate the tests

## Run the tests

```bash
mvn test
```

The build is **expected to fail** on the first run. The three `testReturnsResult` tests for `area()`, `perimeter()`
and `diameter()` fail with a `TODO` message. TestBuddy cannot know the correct value of a formula, so it leaves
the expectation for you to write. Until you do, the test fails; it never passes silently.

To see one pass, replace the TODO in `CircleMethodAreaTest` with the formula:

```java
assertThat(result).isEqualTo(Math.PI * radius * radius, within(1e-9));
```

Generated code in TestBuddy keeps the `Generated by TestKit` header. Put your own tests in a separate file, such as
`CircleExtraTest.java`, so regeneration does not overwrite them.

## Generate the tests with TestBuddy

1. Open the project in IntelliJ and let it build once.
2. Right-click `Circle.java` in each module → **TestBuddy → Generate Test**.
3. Compare the two generated files: `demo/core/CircleTest.java` and `demo/jakarta/CircleTest.java`.

With Pro, you can also enable **Always split** and change the naming in **Settings → Tools → TestBuddy**, and
compare the split output with the single file.

## Compile with `-parameters`

TestBuddy matches constructor rules to fields by parameter name. Java drops those names unless the compiler is
told to keep them. This project sets `-parameters` in `pom.xml`. If you build the classes in IntelliJ, add it too:

**Settings → Build, Execution, Deployment → Compiler → Java Compiler → Additional command line parameters:**
`-parameters`

Without it, the core module's generated tests fail with `missing @Min/@Max` warnings and a placeholder file.

## What to look for

- **Core module:** the constructor is the only check, so the rejects tests call the constructor and expect an exception.
  The failure message names the field and what to fix.
- **Jakarta module:** the constructor accepts any value. The rejects tests ask the validator for a violation on the
  field. A class that does not carry the annotation fails the test.
- **Both:** the field tests, the constructor-creation tests and the getter tests pass as soon as the class is correct.
